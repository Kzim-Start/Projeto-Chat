IMPORTANTE: NÃO mude a estrutura do projeto, as mecânicas, sistemas, regras, fases, progressão, inimigos, personagens, economia, lógica de moedas, chefes, salas, objetivos, menus ou qualquer outra funcionalidade já definida anteriormente.

Tudo que já foi planejado em relação ao funcionamento do jogo deve continuar exatamente igual.

A alteração deve ser somente para melhorar a qualidade visual do projeto.

## NOVA DIREÇÃO VISUAL

O jogo deverá utilizar um estilo:

- 3D estilizado;
- low-poly de boa qualidade;
- visual limpo;
- formas suaves;
- aparência moderna;
- fantasia sombria estilizada;
- sem tentar atingir realismo;
- visual semelhante a jogos indie modernos;
- personagens com proporções levemente cartunizadas;
- cenários simples, porém visualmente bonitos;
- boa leitura visual durante o combate.

Evite:

- modelos excessivamente quadrados;
- aparência de protótipo;
- materiais genéricos;
- assets com estilos diferentes entre si;
- visual extremamente infantil;
- realismo fotográfico;
- modelos excessivamente detalhados e pesados.

O objetivo é encontrar um equilíbrio entre:

QUALIDADE VISUAL + DESEMPENHO + FACILIDADE DE PRODUÇÃO.

---

## BLENDER

Sempre que for adequado, utilize o Blender para criar ou preparar os assets 3D do projeto.

O Blender deverá ser utilizado principalmente para:

- personagens;
- inimigos;
- chefes;
- armas;
- cajados;
- árvores;
- pedras;
- ruínas;
- construções;
- paredes;
- pisos;
- portais;
- baús;
- objetos de cenário;
- elementos decorativos;
- partes modulares das arenas.

Os modelos devem ser pensados para utilização em jogo.

Não criar modelos extremamente detalhados.

Priorizar:

- low-poly estilizado;
- silhuetas bem definidas;
- geometria limpa;
- poucos polígonos;
- boa aparência mesmo vista de longe;
- facilidade de animação;
- facilidade de reutilização;
- boa performance.

---

## CONSISTÊNCIA VISUAL

Todo o jogo deverá seguir a mesma linguagem artística.

Não quero que um personagem pareça pertencer a um jogo e o cenário a outro.

Defina e mantenha padrões para:

- proporção dos personagens;
- tamanho dos objetos;
- formato das construções;
- materiais;
- iluminação;
- saturação;
- nível de detalhe;
- espessura das formas;
- estilo das armas;
- estilo das magias;
- estilo dos inimigos.

Os assets novos devem sempre respeitar essa direção artística.

---

## PERSONAGENS

Os personagens devem ser estilizados e visualmente interessantes, mas sem complexidade desnecessária.

Utilize:

- corpo simplificado;
- silhueta forte;
- roupas estilizadas;
- capas;
- cajados;
- acessórios;
- elementos visuais que indiquem o tipo de magia.

Por exemplo:

Mago de Gelo:

- roupas com tons frios;
- elementos de gelo;
- cristais;
- cajado relacionado ao elemento;
- efeitos sutis de energia;
- olhos ou detalhes mágicos iluminados.

Mago de Fogo:

- elementos quentes;
- detalhes que lembrem brasas;
- peças parcialmente queimadas;
- luzes ou runas relacionadas ao fogo.

Mago de Raio:

- elementos relacionados a eletricidade;
- cristais;
- detalhes energizados;
- pequenos efeitos elétricos.

Não alterar a função de nenhum personagem já definido.

Somente melhorar sua representação visual.

---

## INIMIGOS

Os inimigos também devem utilizar design estilizado.

Cada tipo de inimigo deve possuir uma silhueta fácil de reconhecer.

Por exemplo:

- inimigos rápidos devem parecer mais leves;
- inimigos pesados devem ter formas maiores;
- inimigos resistentes devem parecer robustos;
- inimigos mágicos devem possuir elementos visuais indicando isso.

Os inimigos não precisam possuir muitos detalhes.

A leitura durante o combate é mais importante.

---

## CENÁRIOS

Os cenários devem ser construídos preferencialmente utilizando peças modulares.

Criar módulos como:

- parede reta;
- parede quebrada;
- canto;
- coluna;
- arco;
- piso;
- escada;
- ruína;
- pedra;
- árvore;
- vegetação;
- decoração;
- iluminação;
- altar;
- portal.

Esses elementos devem poder ser combinados para criar diferentes salas e arenas sem necessidade de criar tudo novamente.

Não alterar o sistema de geração, estrutura ou funcionamento das salas.

Somente substituir ou melhorar a aparência visual delas.

---

## CÂMERA

Manter o conceito de câmera isométrica ou perspectiva isométrica já planejado.

A câmera deverá:

- permanecer elevada;
- ficar inclinada em direção ao personagem;
- permitir boa visualização da arena;
- permitir enxergar inimigos ao redor;
- destacar efeitos de magia;
- evitar movimentos excessivos.

Preferencialmente:

- aproximadamente 35° a 50° de inclinação;
- aproximadamente 45° de rotação horizontal;
- distância suficiente para visualizar combate e cenário.

Não transformar o jogo em terceira pessoa tradicional.

---

## MATERIAIS

Utilizar materiais estilizados e relativamente simples.

Evitar texturas extremamente realistas.

Priorizar:

- cores bem definidas;
- roughness controlado;
- detalhes suaves;
- emissão em elementos mágicos;
- materiais reutilizáveis.

Sempre que possível, utilizar poucos materiais por modelo para melhorar desempenho.

---

## ILUMINAÇÃO

A iluminação será uma parte importante do estilo visual.

Utilizar:

- iluminação ambiente controlada;
- luzes direcionais;
- luzes localizadas;
- luzes próximas de magias;
- tochas;
- portais;
- cristais;
- efeitos mágicos.

A fantasia sombria não significa deixar tudo extremamente escuro.

O jogador precisa enxergar claramente:

- personagem;
- inimigos;
- ataques;
- chão;
- obstáculos;
- itens.

Utilizar contraste para criar atmosfera sem prejudicar a jogabilidade.

---

## EFEITOS VISUAIS

Grande parte da qualidade visual deve vir dos efeitos.

Criar VFX estilizados para:

- gelo;
- fogo;
- raio;
- impactos;
- explosões;
- morte de inimigos;
- dano;
- cura;
- coleta de moedas;
- abertura de baús;
- portais;
- chefes.

Exemplo de ataque de gelo:

1. energia aparece no cajado;
2. projétil é lançado;
3. existe um pequeno rastro visual;
4. ocorre impacto;
5. partículas de gelo aparecem;
6. cristais podem surgir;
7. caso exista congelamento, o inimigo recebe feedback visual;
8. ao quebrar, partículas podem ser liberadas.

Esses efeitos devem ser bonitos, porém otimizados.

---

## ANIMAÇÕES

Quando necessário, utilizar Blender para preparar:

- rig;
- idle;
- caminhada;
- corrida;
- ataque;
- dano;
- morte;
- conjuração;
- animações especiais.

Evitar dezenas de animações desnecessárias.

Utilizar somente as necessárias para proporcionar uma boa sensação de gameplay.

As animações devem ser estilizadas e fáceis de ler.

---

## PERFORMANCE

Todos os assets devem considerar desempenho desde o início.

Priorizar:

- modelos low-poly;
- reutilização de materiais;
- objetos modulares;
- instancing quando possível;
- LOD quando necessário;
- partículas controladas;
- iluminação otimizada;
- poucas texturas grandes;
- reutilização de texturas;
- evitar shaders excessivamente pesados.

O objetivo é permitir que o jogo rode bem mesmo em hardware intermediário.

---

## FLUXO DE DESENVOLVIMENTO

A partir de agora, ao continuar o projeto, siga esta lógica:

1. preservar completamente tudo que já funciona;
2. não reestruturar sistemas sem necessidade;
3. identificar assets provisórios;
4. substituir gradualmente assets provisórios por versões estilizadas;
5. utilizar Blender quando realmente melhorar o resultado;
6. manter escala e padrão consistentes;
7. integrar o asset ao projeto;
8. testar visualmente;
9. testar desempenho;
10. continuar para o próximo elemento.

Não refazer o projeto do zero.

Não substituir sistemas já funcionais sem motivo.

Não alterar arquivos que não tenham relação direta com a mudança necessária.
